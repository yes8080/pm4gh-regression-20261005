# exceptions — 异常处理（纯规则）

> **何时读**：`scripts/preflight.sh` 有 `[FAIL]`、必需检查卡住、发现流程缺陷、或需求出现歧义时。
> 口径：本文件**只有规则**（触发 → 动作）＋ §4 的**判据抽查表**（事实清单，不是叙事）。**禁止**写事故经过 / 时间线 / 复盘叙事；
> 平台层面的坑登记在 [traps.md](traps.md)，分步命令与判据在 [flow.md](flow.md)。

## 1. 触发 → 动作

| # | 触发 | 动作 |
|---|---|---|
| 1 | `scripts/preflight.sh` 输出含 `[FAIL]` | **停下**，按原文修完再动；**禁止**绕过，**禁止**先推进别的步骤 |
| 2 | 某必需检查**永久 pending**（同一 SHA 上始终不出结论） | 核对**该检查 job 的 `name:`** 与规则集里的必需 context 是否**逐字一致**（context = job 的 `name:`，**不是** workflow 文件名、**不是** workflow 的 `name:`）；并确认该工作流**无** `paths` / `branches` 过滤、监听 `pull_request` |
| 3 | `mergeStateStatus=BLOCKED` 但 `reviewDecision=APPROVED` | 判定该 SHA 的检查结论**已固化** → **推新提交**；只改 PR 正文 / 标签**不会**重跑检查 |
| 4 | **发现流程缺陷**（脚本 / 工作流 / 文档与实际不符） | **开 Bug Issue**：复现 / 期望 / 实际 / 影响 / 缓解；**禁止**在当前 PR 里顺手改掉 |
| 5 | **发现需求歧义** | **问** Issue 作者 / dispatcher，拿到答复再动；**禁止**自行扩大范围 |
| 6 | PR 正文 **>32KB** | `policy/linked-issue` 历史上会**误报**「缺少关闭关键字」（32KB 处 EPIPE，已修）→ 正文尽量精简；长正文以**最新 SHA** 的门禁结论为准 |
| 7 | 分支名不合规且需**终止**分支 | 走 `scripts/abort.sh <issue#>`（先 `--dry-run`）；**可见性边界**见 [traps.md](traps.md) |

## 2. 处置纪律

1. 门禁 FAIL → **报原文**；**禁止**改门禁 / 放松断言 / 删检查来"修好"。
2. 必需检查必须在**最新 SHA** 上全 `pass` 才进下一步；"先失败后通过"在该 SHA 上不可逆（见陷阱 1）。
3. 状态迁移只走 `scripts/status.sh`（**写迁移必须带 `--as author|reviewer|dispatcher`**，缺 → fail-closed 拒绝；只读模式不需要）；**禁止**手工 `gh issue edit` 增删 `status/*`（HTTP 层是两次并发 mutation）。
4. 无法用**真实输出**证明的事 → **禁止**断言；证据 = 命令 + 真实输出 / 检查名 / 运行链接。
5. 返修在**同一分支**；被打回后状态回 `in-progress`，**禁止**另开 PR。
6. 越界请求（改线上规则集 / 标签、增删脚本、改必需检查 job `name:`）→ **停下问** dispatcher。

## 3. 卡住时的最小取证（给 dispatcher 的固定三件套）

- **原始输出**：逐字贴 `[FAIL]` / `::error::` 那一行，不改写、不摘要。
- **定位**：命令 + `文件:行`（或检查名 + 运行链接）。
- **已排除项**：已核对的相邻条件（如 job `name:` 逐字一致、该 SHA 上的结论、是否最新 SHA）。

## 4. 三态显式原则（C2）

**规则**：每个断言 / 检查必须能区分 **通过（PASS）／失败（FAIL）／未执行（SKIP）** 三态。

1. **三态必须各自可辨且打印**：通过 → `[ OK ]`（或等价成功行）；失败 → `[FAIL]` / `::error::`（带 `file:line` 与修法）；**未执行 → `[ SKIP ]`**（或等价的显式说明行，**必须**写出「为什么没执行＋怎么补跑」）。
2. **未执行不得计入通过**：跳过要**单独计数**并出现在摘要里（`通过 N ／ 失败 M ／ 未执行 K`）；**禁止**用"通过"的措辞覆盖未执行；**禁止**静默跳过（连"本步未运行任何 X"都不打印的，视为违反本条）。
3. **解析不到 ≠ 通过**（fail-closed）：判据抽不到输入（文件缺失 / 标记区为空 / 正则零命中 / 列表为空）时判**失败**，不得判通过。
4. **确认不是空断言**：只跑正向样本的判据等于没有判据 —— 每个判据**必须**自带反向样本（改坏 → 必须失败），并在日志里打印反向样本的结论（见 §2.1 与 [traps.md](traps.md) 陷阱 17）。
5. **未执行的唯一合法来源**：① 前置条件不成立（缺凭据 / 无 `tests/` / 目标仓库没有该对象）；② 该行被**显式标记**为非可执行示例（见 `ci/test` 的文档命令判据：`<!-- 非可执行示例 -->`，标记行会被逐条打印）。**两者都必须留下可查的日志行。**

## 5. 证据纪律（C6）

**规则**：结论必须能被复核 —— 说清"证据是什么类型"、"引用的规则确实存在"、"没观察到"不等于"没发生"。

1. **标注证据类型**：每条结论写明 **实测**（命令 + 真实输出 / 检查名 + 运行链接）或 **推断**（由 X 推得，**未**验证）。**推断不得写成事实**；两者混排时逐条标注。禁止"已测试通过""应该没问题"这类无证据断言（同 §2.4）。
2. **引用规则前必须验证其存在**：引用任何"规则 / 判据 / 脚本 / 文档"前，先确认它**存在**（`grep` / `ls` / 打开对应 `文件:行`）。引用不存在的规则 → 该结论**无效**，先修引用再下结论。
3. **"未观察到" ≠ "没有发生"**：只能写「在 **X 范围内**未观察到 **Y**（取样方式：命令 / 时间窗 / 对象）」。**禁止**把"没查""查不到""解析失败"表述为"不存在""没有发生""不会发生"。
4. **计数类结论必须先看上下文**：命中数（`grep -c`）不是事实，**命中内容**才是；下结论前逐条看过命中行（把"提及"当"命令行"、把"注释"当"平台行为"都是同一类错）。
5. **反例形态**（只写形态，不写经过）：① 把未核实的计数直接写成"有 N 处会失败"；② 把脚本注释当平台行为（未实测）；③ 把"取值/解析失败"当作"无需断言"；④ 用"未复现"推断"不存在"。

## 6. 证据可追溯（C7）

**规则**：PR 正文里**每个**证据块都必须带产生它的 SHA —— 形态唯一、稳定可解析，一行一个：

`<!-- evidence sha=<7-40 位小写 hex> -->`

1. **自动注入**：`scripts/deliver.sh <issue#> --as author` 在推送后把每个标记的 sha 改写为**推送后的** `origin/<branch>` head 并回读校验（本地 HEAD ≠ 远端 head → 直接失败，不写 PR 正文）。**正文零标记 → 脚本直接失败**（不推送、不建/更新 PR）。
2. **标记只在围栏（三反引号 / `~~~` 围起来的代码块）之外生效**：围栏内是证据正文 —— 粘进来的输出本身可能**包含标记样例**（例如本判据的反向样本原文），它不参与判定、也**不被注入改写**（改写 = 动证据原文，正好违反 C7 的可追溯初衷）。判定范围 = 围栏外那些标记。
3. **判据**（唯一一处实现 = `ci/test`）：围栏外**所有**标记的 sha 必须 == 该 PR 的 `head.sha`。判定 = head SHA 以标注值为**前缀**（40 位时即「相等」；7 位短 SHA 仍唯一指向同一提交）。
4. **不一致 → `[FAIL]` 并指出是哪一块**：块序号 + 正文行号 + 所在小节标题 + 可直接粘贴的规范标记；含 `evidence` 的 HTML 注释形态不合规（缺 `sha=` / 非 hex / 超长）同样 `[FAIL]` —— 不给出「把标记写坏」的逃逸口。
5. **零标记的语义（本仓库选择：FAIL，不是 SKIP）**：规则 1 要求"每个证据块必须带 SHA"，零标记 = 一个都没声明；若判「未执行 / 不适用」而放行，**删掉标记**就是唯一逃逸口，判据整体失效。三态在此仍成立：判据**从不**用通过措辞掩盖零标记，而是打印 `[FAIL] 未声明证据块` + 可直接粘贴的规范标记。**禁止**把零标记判成 `[ OK ]`（= 静默通过）。
6. **换 SHA 后必须重跑**：推新提交后旧标记即失效（head 变了）→ 门禁 `[FAIL]`，直到在该 SHA 上重跑并重新交付（`scripts/deliver.sh <issue#> --as author`）。

### 边界（**不得**过度宣称）

1. 本判据验的是**标注一致性** —— 产物**声称**来自哪个 SHA。它把"照搬**别处**的证据"变成机器可判（照搬块的 SHA ≠ head → `[FAIL]`）。
2. 它**不能**判定**内容真伪**：无法判定那段输出是否真来自那次运行 —— 照抄**同一 SHA** 上的旧输出、手工编造输出、在别的机器上跑，都判不出。
3. **禁止**据此宣称"能验证据真伪"/"证据已验真"（§5.1：实测与推断必须逐条标注；"能验真伪"是推断，不是事实）。
4. 标记**不是签署**：作者可以在没运行的情况下写上正确 SHA。可判的是"是否与 head 一致"，不是"是否真的跑过"。
5. 本片**未做**：① 未判"哪些文字算证据块"（无载体，判不出形状）；② 未把证据内容与 SHA 上的运行日志比对（运行日志不在 PR 正文里，无载体）—— 缩小后的不可判定面**只剩内容真伪**（人审 / 交叉复核的范围）。
